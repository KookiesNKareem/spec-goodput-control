# Roadmap: Quantized-Clone Speculation → Public Result

Date: 2026-06-11. Status: Phase 1 in progress.

## Where we are

Three experiment phases complete on a rented A40 (vLLM 0.6.3.post1, Qwen2.5):

1. Verifier-aware draft quantization (scale/clip perturbation): **failed**, documented.
2. Mixed-precision layer protection: improves acceptance, never throughput — **steering negative**.
3. Quantized-clone speculation (AWQ copy of target as draft, FP target verifier): **works**.
   3B: +10-12% at B1-8, crossover B12-16. 7B: +17-55% at B1-16, crossover B24-32.
   Adaptive controller (`auto_quant_spec_controller.py`) recovers fixed-sweep oracle online
   using completed-request wall-clock goodput reward; load-shift demo passes.

## Prior-art landscape (checked 2026-06-11)

- **QuantSpec** (ICML 2025, arXiv:2502.10424): quantized self-speculation (W4 + hierarchical
  quantized KV), long-context focus. Owns the "quantized clone as draft" idea.
- **QSpec** (2024): W4A4 draft / W4A16 verify on shared weights.
- **SmartSpec** (arXiv:2406.14066): dynamic speculation length from *estimated* goodput
  (modeled acceptance); never merged into vLLM.
- **BanditSpec** (arXiv:2505.15141): bandit choice of spec-decode hyperparameters,
  *simulated* serving.
- **vLLM RFC #4565** (automate spec decode): closed as not planned. Milestone 3
  ("runtime metrics instead of pre-profiled data") never built.
- **vLLM PR #26504** (DynamicProposer / eagle_dynamic): per-request adaptive k targeting
  an *acceptance-rate* threshold. Live now.

## The defensible claim

Acceptance-based and offline-profiled speculation control are both wrong under real load.
A measured request-level goodput bandit recovers the oracle online, training-free, in a
real engine. The useful speculation regime scales with verifier cost (3B vs 7B crossover).
Our own data shows acceptance is a misleading signal (gamma 1 maximizes acceptance; gamma
2-3 wins throughput at low/mid batch) — directly relevant to PR #26504's design.

## Phase 1 — Harden (week 1-2, current A40)

1. Real workload: ShareGPT prompts in `spec_decode_quant_bench.py`; rerun 7B crossover
   sweep (target + gamma 1/2/3 × B1-32) with repeats.
2. Baselines at 7B: n-gram/prompt-lookup, small AWQ draft (0.5B/1.5B), and a reimplementation
   of PR #26504's acceptance-targeting policy — head-to-head vs goodput controller.
3. Arrival-process experiment: Poisson arrivals at 3-4 QPS levels, latency percentiles,
   controller vs fixed-gamma vs off.
4. If it fits: 14B FP16 + AWQ clone (≈37 GB weights on 46 GB) for a third crossover point.

## Phase 2 — Publish artifact + engage upstream (week 2-3)

- Clean public repo + blog post / arXiv note.
- Data-backed comment on vLLM PR #26504 and/or fresh RFC: evidence that acceptance-targeting
  picks the wrong gamma under load; propose measured-goodput reward. Time-sensitive — do
  before the PR merges.

## Phase 3 — Decide on paper (~week 4)

Workshop paper / arXiv preprint is the floor. Main-venue (MLSys 2027, fall deadline) only
if hardened results stay strong vs EAGLE-class baselines. Decision input: Phase 2 reception.

## Known gaps to keep honest about

- Memory cost of the clone (~25% of target weights) reduces KV budget; report it.
- vLLM 0.6.3 is two majors old; results are about the *method*, not current engine numbers.
- Reversible off for active sequences still needs draft-KV catch-up (request-level off works).
- B32 controller picks gamma 1 when target-only is marginally better; needs target-only arm
  or high-load margin.
